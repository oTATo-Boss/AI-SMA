# AI-SMA · 账号运营项目模板

AI-SMA（AI-Social Media Automation）是给 Codex 和 Claude Code 用的社交媒体账号运营项目模板。新建一个账号就生成一个独立的项目文件夹：你只和账号的**总负责人**对话，总负责人派 8 个子智能体（市场研究、创意总监、创意评审、导演、素材制作、后期、审片、增长分析）调研、出创意、制作、审片，最后交付完整内容包。

- 每个智能体是 `agents/role/` 下一个独立的文件夹：说明书、配置卡、记忆，用到的带知识和工具。在这个账号里用得越多，记忆里的经验越多，下次开工先读。
- Codex 为主，Claude Code 也能用：两个软件的子智能体登记文件由脚本根据配置卡生成，说明书两边通用。
- 开工阶段（定方向）会问你；之后说一句"做一条视频"，团队自己完成，中途不找你，你只验收成品和发布。
- 只交付、不发布。智能体只在 `agents/` 里写：固定资产和发布内容只读，交付只增不改，两个软件都有写入保护。

一个账号就是一个项目文件夹：账号档案、记忆、数据和记录都在自己的文件夹里，账号之间不共享、不互相引用。适合一个人运营小红书、抖音等短视频账号，内容主要靠 AI 生成和代码视频完成。

## 快速开始

1. 给账号新建一个文件夹，比如 `~/Desktop/@账号名`，在里面打开 Codex（或 Claude Code）。
2. 发这一句：

   > 使用 https://github.com/oTATo-Boss/AI-SMA 把当前文件夹配置成账号项目。

3. 部署完总负责人会直接回复：怎么用、要准备什么、要你回答的几个问题。按提示在 Codex 里信任这个文件夹、新开一个对话，回答完问题就能开工。

账号名默认取文件夹名（去掉开头的 @）。Chrome 个人资料不用事先准备，要让智能体查看平台后台时再建。

**不用智能体，自己在终端部署**：

```bash
git clone https://github.com/oTATo-Boss/AI-SMA.git
```

```bash
python3 AI-SMA/新建账号.py --dest ~/Desktop/@账号名
```

部署完在这个文件夹打开 Codex（或 Claude Code），Codex 问时选信任这个文件夹，随便说一句，总负责人会接着带你开工。

- 目标文件夹可以已经建好，但里面只能有隐藏文件；脚本不覆盖任何已有文件。不写 `--dest` 就部署到当前文件夹。
- 可选参数：`--name` 指定账号名，`--browser-profile` 填 Chrome 个人资料名。
- 脚本会复制 `骨架/`、填入账号名、生成两个软件的子智能体登记、写第一条日志、生成任务总览，再运行项目检查和环境检查，列出所有"待填写"的位置。

## 给智能体的部署步骤

收到"用这个仓库把当前文件夹配置（或部署）成账号项目"的请求时，按顺序做：

1. 部署目标就是当前会话打开的文件夹，不用再问。不要把仓库克隆进这个文件夹。
2. 把仓库克隆到临时目录，运行 `python3 <临时目录>/新建账号.py --dest "<当前文件夹>"`。账号名默认取文件夹名；本人另说了账号名就加 `--name`；文件夹名看不出账号名（比如"未命名文件夹"）本人又没说，先问。脚本说文件夹里已有文件时，停下来问本人是不是开错了文件夹。
3. 部署完读新项目根目录的 `AGENTS.md`、`agents/role/总负责人/AGENT.md` 和 `agents/role/总负责人/知识/开工.md`，按开工流程第 1 节马上回复本人：怎么用、要准备的、要回答的问题。
4. 之后你就是这个项目的总负责人，按它的说明书继续。缺的工具和技能本人确认后再装，登录和输入 Key 由本人操作。子智能体要等本人信任这个文件夹、新开对话后才会被 Codex 认出来。

## 需要什么

- macOS 或 Linux（任务管理工具用到 fcntl，Windows 不支持）
- Python 3.9+、ffmpeg／ffprobe、Node 18+、git、Google Chrome
- Codex（推荐）或 Claude Code。两边都有子智能体和写入保护；Codex 要本人信任项目文件夹后才读项目里的设置，写入保护还要本人在 Codex 里批准一次。项目预设了自动放行（Claude 自动接受编辑和常用命令，Codex 的命令可以联网），本人第一次打开时在信任提示里确认；删除文件、写项目以外的地方仍然会问
- 技能：见 `骨架/agents/SKILLS_INDEX.md` 的"来源"列，至少装齐"必需"的 social-media 六个技能
- 可选：HeyGen CLI（配乐、音效）、ChatGPT 桌面 App（Claude 通过 Codex 生图）、RunningHub 账号（AI 视频生成，付费）

不用事先逐项核对：部署时会自动跑环境检查，缺什么都会列出来并给出补法。

## 工具和技能怎么装

工具、技能和登录是本机软件，所有账号项目共用，不复制进项目；账号的信息不共用。

1. 基础工具：macOS 先装 Homebrew，再 `brew install python ffmpeg node git`；安装 Google Chrome。
2. 技能：按 `骨架/agents/SKILLS_INDEX.md` 的"来源"安装。Codex 读 `~/.agents/skills` 和项目里的 `.agents/skills`，Claude Code 读 `~/.claude/skills` 和项目里的 `.claude/skills`。
3. 用到才需要：ChatGPT 桌面 App（自带 codex-cli，Claude 生图用）；HeyGen CLI（官方脚本安装后本人运行 `heygen auth login --oauth`）；RunningHub Key（本人用 RH-minimax-H3 的 `credentials.py set` 隐藏输入）；`python3 -m pip install requests`。
4. 要让智能体只读查看平台后台时：在 Chrome 里给这个账号建一个个人资料并登录平台，把资料名告诉总负责人（写进 `agents/账号/账号配置.yaml` 的 browser_profile）。每个账号用自己的资料。

装完在项目里运行 `python3 agents/公共/工具/环境检查/检查环境.py`，直到"结果：通过"。

## 开工之后

部署后总负责人按 `agents/role/总负责人/知识/开工.md` 带你开工：先回答 6 个必答问题（账号是谁、目标、平台、品牌露出、出镜和声音、制作方式），回答写进账号档案；再做一轮定位，新号按总负责人的 `知识/定位与对标.md`，已有粉丝或历史内容的账号按 `知识/转型与重启.md`。

账号策略的顺序是固定的：诊断 → 对标 → 定位方案（至少 3 个方向）→ 你确认 → 内容策略 → 选题。你调整方向时，总负责人会先按"保留／放弃／新增"复述，等你确认；定位没确认前不出具体选题。定位确认、选题池写好后，开工阶段结束（`agents/账号/账号配置.yaml` 的 stage 改成"已开工"）。

之后直接说"做一条视频"这类一句话任务。总负责人派团队：调研 → 多路创意 → 盲评 → 方案 → 制作 → 合成 → 审片 → 交付，中途不找你；任务所需的付费生成、参考素材上传和范围内返工直接执行，无需首次、逐批或扣费确认。只在需要登录、其他授权或 Key、返工轮数用完、拿不准版权和平台规则时停下来找你。同时干活的子智能体数和返工上限在 `agents/账号/账号配置.yaml` 的 autonomy 里改。

每次收工，参与的子智能体各自记一笔记录；评审、审片的意见和你的验收意见也会记进负责那部分的智能体的记录，攒够了提炼进它的经验，下次开工先读。

改完规则运行 `python3 agents/公共/工具/项目检查/检查.py`，确认没有失效链接和配置不一致。

## 项目结构

```text
@账号名/
├── AGENTS.md、CLAUDE.md    入口：红线和分工（Codex、Claude 自动加载）
├── 固定资产/               品牌和角色等原始资产，智能体只读
├── 发布内容/               本人采用并归档的内容，智能体只读
├── 交付/                   完整交付，只能新增全新目录
├── agents/
│   ├── role/               9 个智能体：总负责人和 8 个子智能体，每个带说明书、配置卡、记忆，有的带知识和工具
│   ├── 账号/               账号档案：配置、事实、定位、规范、偏好、对标、爆款、数据
│   ├── 公共/               细则、交接合同、共用工具
│   └── 工作/               每个任务一个目录、任务总览、日志
├── .codex/                 Codex 的子智能体登记和并行上限（生成）、写入保护
└── .claude/                Claude 的子智能体登记（生成）、写入保护
```

| 类别 | 文件 | 怎么处理 |
|---|---|---|
| 通用 | 入口、`agents/README.md`、各智能体的说明书、配置卡、知识和工具、`agents/公共/`、`.claude/settings.json`、`.codex/hooks.json`、`.ignore` | 原样使用；改了配置卡运行生成脚本 |
| 账号填写 | `agents/账号/` 里的账号配置、账号信息、定位与策略、内容与交付第 1–3 节、偏好、外部知识、选题池、附录；技能目录 | 开工时由总负责人带着填，其余工作中补 |
| 运行中产生 | 各智能体的 `记忆/`、`agents/工作/`、`agents/账号/` 的对标库、爆款库、数据和历史资料、`交付/`、`发布内容/`、`固定资产/` | 空目录开始 |

## 维护模板

维护模板时先读 `AGENTS.md`。改完必须试部署一次；影响智能体怎么干活的改动，能实际跑一次的先跑，还没实跑过的写进下面"待决"；每次发版在"版本"里记一行。

## 待决

- 技能来源：33 个技能里 31 个来源已确认；video-frames、bs-hyperframes-velocity-sting 只有部分信息。许可写"未声明"的技能，别人使用前要自己确认。
- 技能安装：以后首次部署时自动给本机装好全部技能、写好技能目录；各智能体自带的技能由作者统一添加。
- 本地审阅台（看板、媒体审阅、确认和批注按钮）：以后再说。
- 多智能体升级的后续：充实市场数据和创意方法（市场数据统一用 Chrome 只读浏览各平台获取；创意方法类外部项目安装前逐个审查来源和许可）；打通制作、真实审片、自动返工和发布后数据回流。
- 编排层：现在由主对话当总负责人，用两个软件自带的子智能体和任务工具记状态；做成软件或平台时再换成独立的编排服务（例如 LangGraph），智能体包和交接合同可以直接沿用。
- Codex：子智能体的沙盒和审批跟着主对话走，靠说明书约束；需要按角色严格限定工具时用 Claude Code。子智能体登记、写入保护和联网放行要本人信任项目、新开对话后才生效，还没在真实使用中实测过。
- 自动放行：Claude 的放行规则和 Codex 的联网放行都还没在真实做内容时实测过。
- 付费生成免确认：已取消首次授权、逐批和扣费确认要求；尚未在真实付费生成任务中实跑验证。
- xiaohongshu-ops-skill（Xiangyu-CAS）没有接入：流程绑定 OpenClaw 浏览器，包含发帖、评论、私信和高度贴合的近似复刻，和红线冲突，而且没有声明许可。
- 客户端全局记忆：现在只靠入口红线 8 要求智能体不参考，Codex 开着记忆时仍会自动带入；以后做成软件或平台时，由平台控制带入的上下文。
- 验收指标：主对话开始时必读不超过 8 千字符；子智能体动手前要读的约 2 万字符以内；部署后检查通过，30 分钟内能开工。
