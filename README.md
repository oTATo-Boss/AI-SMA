# AI-SMA · 账号运营项目模板

AI-SMA（AI-Social Media Automation）是给 AI agent（Claude Code、Codex）用的社交媒体账号运营项目骨架。新建一个账号就生成一个独立项目，里面有：

- 入口：6 条红线和"什么任务读什么"的路由，agent 启动时自动加载；
- 长期规范：账号配置、定位与策略、内容与交付等，按账号填写；
- 五类 SOP：账号定位与对标、生成类视频、代码类视频、发布材料交付、数据分析与反馈；
- 工具：任务管理（状态、确认、交付版本）、项目检查、环境检查、写入保护、发布包。

一个账号就是一个项目文件夹：规范、资料、数据和记录都在自己的文件夹里，账号之间不共享、不互相引用。

适合一个人运营小红书、抖音等短视频账号，内容主要靠 AI 生成和代码视频完成：agent 负责策划、制作、检查和整理交付，本人负责确认、验收和发布。

## 快速开始

1. 给账号新建一个文件夹，比如 `~/Desktop/@账号名`，在里面打开 Claude Code 或 Codex。
2. 发这一句：

   > 用 https://github.com/oTATo-Boss/AI-SMA 把当前文件夹部署成账号项目。

3. 部署完 agent 会直接回复：怎么用、要准备什么、要你回答的几个问题。回答完就能开工。

账号名默认取文件夹名（去掉开头的 @）。Chrome 个人资料不用事先准备，要让 agent 查看平台后台时再建。

**不用 agent，自己在终端部署**：

```bash
git clone https://github.com/oTATo-Boss/AI-SMA.git
```

```bash
python3 AI-SMA/新建账号.py --dest ~/Desktop/@账号名
```

部署完在这个文件夹打开 Claude Code 或 Codex，随便说一句，agent 会接着带你开工。

- 目标文件夹可以已经建好，但里面只能有隐藏文件；脚本不覆盖任何已有文件。不写 `--dest` 就部署到当前文件夹。
- 可选参数：`--name` 指定账号名，`--browser-profile` 填 Chrome 个人资料名。
- 脚本会复制 `骨架/`、填入账号名、写第一条日志、生成任务总览，再运行项目检查和环境检查，列出所有"待填写"的位置。

## 给 agent 的部署步骤

收到"用这个仓库把当前文件夹部署成账号项目"的请求时，按顺序做：

1. 部署目标就是当前会话打开的文件夹，不用再问。不要把仓库克隆进这个文件夹。
2. 把仓库克隆到临时目录，运行 `python3 <临时目录>/新建账号.py --dest "<当前文件夹>"`。账号名默认取文件夹名；本人另说了账号名就加 `--name`；文件夹名看不出账号名（比如"未命名文件夹"）本人又没说，先问。脚本说文件夹里已有文件时，停下来问本人是不是开错了文件夹。
3. 部署完读新项目根目录的 `AGENTS.md` 和 `agent/sop/新账号开工.md`，按开工 SOP 第 1 节马上回复本人：怎么用、要准备的、要回答的问题。
4. 之后按新项目的 `AGENTS.md` 和开工 SOP 继续。缺的工具和技能本人确认后再装，登录和输入 Key 由本人操作。

## 需要什么

- macOS 或 Linux（任务管理工具用到 fcntl，Windows 不支持）
- Python 3.9+、ffmpeg／ffprobe、Node 18+、git、Google Chrome
- Claude Code 或 Codex。写入保护钩子只对 Claude Code 生效，Codex 按入口红线执行
- 技能：见 `骨架/agent/SKILLS_INDEX.md` 的"来源"列，至少装齐"必需"的 social-media 六个技能
- 可选：HeyGen CLI（配乐、音效）、ChatGPT 桌面 App（Claude 通过 Codex 生图）、RunningHub 账号（AI 视频生成，付费）

不用事先逐项核对：部署时会自动跑环境检查，缺什么都会列出来并给出补法。

## 工具和技能怎么装

工具、技能和登录是本机软件，所有账号项目共用，不复制进项目；账号的信息不共用。

1. 基础工具：macOS 先装 Homebrew，再 `brew install python ffmpeg node git`；安装 Google Chrome。
2. 技能：按 `骨架/agent/SKILLS_INDEX.md` 的"来源"安装。Claude Code 读 `~/.claude/skills` 和项目里的 `.claude/skills`，Codex 读 `~/.codex/skills`。
3. 用到才需要：ChatGPT 桌面 App（自带 codex-cli，Claude 生图用）；HeyGen CLI（官方脚本安装后本人运行 `heygen auth login --oauth`）；RunningHub Key（本人用 RH-minimax-H3 的 `credentials.py set` 隐藏输入）；`python3 -m pip install requests`。
4. 要让 agent 只读查看平台后台时：在 Chrome 里给这个账号建一个个人资料并登录平台，把资料名告诉 agent。每个账号用自己的资料。

装完在项目里运行 `python3 agent/tools/环境检查/检查环境.py`，直到"结果：通过"。

## 开工之后

部署后 agent 按新项目的 `agent/sop/新账号开工.md` 带你开工：先回答 6 个必答问题（账号是谁、目标、平台、品牌露出、出镜和声音、制作方式），回答写进对应的规范；再做一轮定位，新号按 `agent/sop/账号定位与对标分析.md`，已有粉丝或历史内容的账号按 `agent/sop/账号转型与重启.md`。

账号策略的顺序是固定的：诊断 → 对标 → 定位方案（至少 3 个方向）→ 你确认 → 内容策略 → 选题。你调整方向时，agent 会先按"保留／放弃／新增"复述，等你确认；定位没确认前不出具体选题。项目检查会核对定位确认记录，也会报出项目里出现的同级其他账号名称。其余"待填写"在工作中逐步补，品牌资产放进 `固定资产/`。

改完规范后运行 `python3 agent/tools/项目检查/检查.py`，确认没有失效链接和配置不一致。

## 项目结构

```text
@账号名/
├── AGENTS.md、CLAUDE.md    入口：红线、启动、任务路由（agent 自动加载）
├── .claude/settings.json   Claude Code 写入保护钩子
├── agent/                  agent 的工作区：规范、SOP、工具、任务、日志、附录、账号数据
├── 交付/                   完整交付，只能新增全新目录
├── 发布内容/               本人采用并归档的内容，agent 只读
└── 固定资产/               品牌和角色等原始资产，agent 只读
```

| 类别 | 文件 | 怎么处理 |
|---|---|---|
| 通用 | 入口的结构和红线、`agent/规范/项目规则.md`、`agent/sop/`、`agent/tools/`、`.claude/settings.json`、`.ignore` | 原样使用 |
| 账号填写 | 账号配置、账号信息、定位与策略、内容与交付第 1–3 节、偏好与经验、外部知识、选题池、附录、技能索引、付费服务授权 | 开工时由 agent 带着填，其余工作中补 |
| 运行中产生 | `agent/工作/`、`agent/log/`、`agent/账号数据/`、`交付/`、`发布内容/`、`固定资产/`、`agent/历史资料/` | 空目录开始 |

## 维护模板

维护模板时先读 `AGENTS.md`。通用文件的改进先在真实账号项目里验证，再同步到 `骨架/`，并在下面"版本"里记一行。升级后按 `测试用例/` 里的场景重放一遍，对照通过标准。

## 待决

- 技能来源：23 个技能里 21 个来源已确认；video-frames、bs-hyperframes-velocity-sting 只有部分信息。许可写"未声明"的技能，别人使用前要自己确认。
- 本地审阅台（看板、媒体审阅、确认和批注按钮）：以后再说。
- 客户端全局记忆：现在只靠入口第 8 条要求 agent 不参考，Codex 开着记忆时仍会自动带入；以后做成软件或平台时，由平台控制带入的上下文。
- 验收指标：启动必读不超过 8 千字符；单个任务动手前要读的项目文档约 2 万字符以内；部署后检查通过，30 分钟内能开工。
