# AI-SMA · 可装配的视频制作项目模板

在 Codex 中说一句需求，把当前空文件夹配置为适合该作品的团队、技能与制作流程。支持单片、系列和长期账号；Codex 为主要部署入口，Claude Code 也可运行。

> 使用 https://github.com/oTATo-Boss/AI-SMA 把当前文件夹配置成 B站科普长视频项目，以代码动画和旁白为主。

也可以配置成产品广告、Launch 演示、剧情电影、短剧／中剧、MV、艺术动效或社媒账号项目。已有的“配置成账号项目”说法仍然有效。

## 一句话部署会做什么

1. 根据内容类型、项目形态、制作路线和发布规格选择模板。
2. 生成该项目需要的专业角色、流程、项目资料和交接合同。
3. **由部署 Codex 实际安装所需的完整技能与必要运行工具**，复用验证通过的已有安装。
4. 检查技能来源、文件、客户端入口和运行状态，报告登录、重载等确实需要本人处理的事项。
5. 总负责人带本人补齐开工简报，之后按任务自主制作、审查和交付。

仓库不携带第三方技能包，也没有自动安装技能脚本。来源、版本、完整包边界和三系统安装说明由 `骨架/agents/公共/技能来源.json` 维护。部署智能体读规则并执行适合用户环境的公开命令；仅写下 skill 名字不算安装。

## 九类模板

| 类型 | 标识 | 主要用途 |
|---|---|---|
| 社媒账号运营 | social-account | 定位、短视频、图文、运营复盘 |
| 长视频与纪录讲解 | long-form | B站／YouTube、教程、采访与纪录讲解 |
| 科普与知识动画 | science | 事实核验、旁白、解释动画 |
| 广告与品牌短片 | advertising | 品牌简报、产品主张、商业短片 |
| Launch 与产品演示 | launch | 真实界面、功能展示、产品发布 |
| 剧情短片与电影 | film | 剧本、分镜、场景和镜头制作 |
| 短剧／中剧／系列剧情 | series | 分集结构、角色资产、跨集连续性 |
| MV 与音乐影像 | music-video | 音乐结构、叙事／表演／歌词影像 |
| 动效与视觉实验 | motion-design | 艺术动画、动态图形、三维视觉 |

MV 可用 `--variant narrative`（叙事）、`performance`（表演）、`lyric`（歌词）装配额外专业角色与剧本流程。

路线可选 AI 生成（ai）、实拍剪辑（live-action）、二维代码动画（code-2d）、三维 CG（cg-3d）；混合制作组合多条路线。平台和画幅独立配置，不把电影或长视频套入社媒短视频规则。

## 给智能体的部署步骤

收到“使用本仓库把当前文件夹配置成 xxx 项目”时：

1. 当前文件夹就是目标；把本仓库取得临时目录，不克隆到目标内。保留用户已有文件。已有本工具部署记录时用恢复模式，不重新创建或覆盖。
2. 读本 README、模板注册表与 `骨架/agents/公共/技能安装.md`。根据请求确定片型、形态、路线和实际客户端；只对影响安装集合且无法判断的缺项集中补问一次。用户明确指定的内容不重复确认。
3. 用 `新建项目.py --plan` 查看装配需求，再运行装配。脚本返回 2 代表已装配、安装或环境仍待完成；不将其报告为完整部署成功。
4. 按装配清单读取来源及安装说明，检查本机共享库与工具。来源、版本和完整包检查通过才复用；缺项由你执行实际安装。仅安装本项目需要的集合及关联资源，保留包内相对路径与许可证，不使用无差别全库安装。
5. 普通技能实体放在用户主目录的 `.agents/skills/<用途分类>/`。更新相关分类索引和 Claude 发现入口。系统／插件由各自渠道管理。同名冲突、独立修改不覆盖，先完成其他准备，再集中说明真正需要本人决定的冲突。
6. 用环境检查器的 `--bind 技能名=实际入口目录 --record` 绑定并验证实际安装；重复参数可绑定多个技能。验证器仅检查和记证据，不执行安装。运行工具也由你按系统补齐。用户部署请求已经包含这些常规安装，不另加逐项许可关卡；登录、Key、管理员授权由本人完成。
7. 运行项目检查和环境检查，分别报告项目结构、技能文件、客户端发现、工具、登录／模型和实跑状态。必要技能缺失或版本冲突时不能报告部署完成；客户端没实际发现只能写待验证或待重载。
8. 读新项目入口和总负责人说明书，集中询问仍缺的项目目标、素材、风格、声音及交付要求。账号模板按账号定位流程；其他模板按对应片型简报。制作过程只使用该项目资料。

新增制作路线时，先更新装配需求、补齐技能并检查，再登记新增角色；不把候选技能当作已分配能力。

## 装配工具

只想预览，不写文件：

```bash
python3 新建项目.py --dest "目标文件夹" --profile science --route code-2d --plan
```

装配项目（不自动安装技能）：

```bash
python3 新建项目.py --dest "目标文件夹" --profile science --route code-2d --client codex
```

Windows 用部署时找到的实际 Python 解释器（例如 `py`）；其余参数相同。可重复 `--route` 组合路线、重复 `--platform` 设置渠道；`--form` 接受 single、series、account；`--execution-mode` 接受 auto、multi、single。`--no-sound`、`--no-voice`、`--no-subtitles` 关闭相应角色，`--voice`、`--subtitles` 显式启用。

- `--list`：列出模板与路线。
- `--resume`：恢复本工具记录的部署，保留用户已有修改。
- `--check`：只检查已有项目。
- `--assemble-only`：只装配，明确保留未验证状态，供结构测试使用。
- `新建账号.py --dest ...`：兼容账号部署入口，生成 v2 社媒项目；不迁移旧账号。

## 团队与项目资料

角色库包含 24 个专业角色。实际项目按模板和路线选取，任务只调度当前阶段需要的角色。职责涵盖制片、研究、编剧、导演、分镜、美术、资产、连续性、AI 镜头、二维／三维、摄影采集、剪辑、合成、对白、混音、字幕、审片、交付与增长。

默认同时运行 3 个子 agent、同一问题最多返工 2 轮，可在项目配置中调整。没有子 agent 能力时按同一合同顺序代行，审查标记为 self，不声称独立盲评。不指定或覆盖用户选择的模型。

项目保留 `固定资产/`、`交付/`、`发布内容/`；工作都在 `agents/` 中。公共配置在 `agents/项目/项目配置.yaml`（JSON 格式的合法 YAML），账号资料仅在账号模板出现。项目、集／章节、场景、镜头／工作包以父子关系和依赖记录，支持中断恢复；上游变动使相关产物待复核。

角色 skills 是正式分配的技能，preload_skills 是启动加载子集。真实安装和当前任务加载是两件事，避免把全库内容塞进每个 agent 的上下文。

## 三系统与运行能力

核心装配、任务、合同和检查工具面向 macOS、Windows、Linux。具体软件、媒体模型和插件另有兼容范围；没有对应工具时按来源清单处理，不能把“文件装好”当成可制作。

基础运行时按选定路线安装，包括 Python、Git、Node、FFmpeg、浏览器或三维工具。API 登录和模型状态单独检查；应用或模型许可不由技能许可证代替。写入钩子提供辅助拦截，不能约束任意脚本的全部行为，不是严格沙盒。

## 验证与维护

```bash
python3 tests/run_suite.py
```

核心 CI 在三个原生系统运行；全部预设均执行临时项目装配、角色／依赖／流程和待填写检查。真实小样与证据见 `验证/v2/README.md`，样片不随用户骨架复制。临时部署目录由测试清理。

修改通用文件后必须试部署。发布前按来源锁验证干净环境安装，核对实际客户端发现和制作路线；真实证据不足时写入下面待决，不能将静态检查冒充 E2E。

## 待决与验证边界

- 三系统核心 CI 和九模板干净技能安装已通过；两客户端完整制作仍未端到端验证（当前 Claude 未登录），四类小样的连续观看与试听仍未完成。具体证据见验证报告。
- 五类非代表模板首版只承诺结构与流程验证，不宣称已做完整成片实跑。
- 电影／剧集支持分段制作和状态管理，小样通过不等于完整长片制作已验证。
- 来源或许可尚未核实的本机改编技能保留为候选，不进入必需安装集合。
- 旧项目不自动升级；公开发布不包含用户账号、凭据、全局记忆或作者本机路径。
