# 共享技能安装与验证

这份规则由执行一句话部署的 Codex 使用。仓库只维护来源与规则，**不提供自动安装脚本**。部署请求已经授权为选定项目安装必要技能和运行工具；按实际系统执行，不要求用户逐条批准普通安装。登录、密钥、系统管理员授权和同名冲突由实际缺口决定，不能编造就绪。

## 先确定本项目需要什么

1. 读取项目配置 `skills.required`，递归合并 `技能来源.json` 中的 `requires`。这是要装齐的集合；候选技能和未选路线不安装。
2. 一个来源包可能包含多个子技能及共享资源，选中其中一个时需要完整保留其 `package_root`。完整包是安装单位，角色分配仍按技能入口；不能只复制 `SKILL.md`，也不任意拆开资源。
3. 核对当前运行的系统、CPU、Python、Git、客户端及已有共享技能。Windows 原生和 WSL 是不同环境，在实际运行环境中安装和检查。
4. 读取 `工具/环境检查/依赖.json`，只安装当前集合要求的运行工具。框架工程的 npm 依赖、语音模型、服务登录与付费服务状态另按实际选定路线检查。

## 实体位置与客户端入口

- 实体统一放在用户主目录的 `.agents/skills/<用途分类>/…`。Windows 对应当前 Windows 用户主目录，不能写作者电脑路径。用途分类沿用本机索引；一个完整包只归属一个用途分类，跨分类角色共享它。
- 保留包内相对布局。比如多个 HyperFrames 技能归属于同一源包 `skills`，安装成 `video/hyperframes-package/` 后，其内部 `hyperframes/`、`media-use/` 等保持兄弟关系；不为了音频分类把包内共享部分拆走。
- Codex 直接发现 `.agents/skills` 实体；Claude Code 在 `~/.claude/skills/<skill-name>` 建逐技能入口，链接指向完整包中的真正技能目录。macOS/Linux 用目录 symlink；Windows 优先目录 junction，实际环境支持时使用 symlink。不能复制第二份实体。
- 已存在同名入口先解析真实目标。新链接不能覆盖旧文件、旧目录或其他来源的链接。技能同名不代表内容相同。
- 系统与插件技能沿用原发行渠道，不复制缓存到共享库。插件仅在来源清单明确支持、客户端实际可用且完整资源核实后才算等价；目前注册表的文件验证不把插件名称当等价证据。

## 获取固定来源：由部署智能体执行

注册表的 `repository`、`ref`、`package_root`、`files` 是准绳；`ref` 必须是完整 Git 提交，不能用会漂移的 main/latest 代替。通用命令配方如下，智能体将占位符替换为已核对的值，并按当前 shell 正确引用路径：

```text
git clone --filter=blob:none --no-checkout --depth 1 <repository> <新的临时目录>
git -C <临时目录> fetch --filter=blob:none --depth 1 origin <ref>
git -C <临时目录> config core.autocrlf false
git -C <临时目录> checkout --detach <ref>
git -C <临时目录> rev-parse HEAD
```

大型仓库可在 checkout 前按 `package_root` 和包外许可证路径设置 sparse-checkout，避免下载无关图片或工程；必须保留注册表列出的整个包与全部资源，不裁剪文件清单。

将该提交的完整 `package_root` 复制到共享库中**不存在的新目标目录**。macOS/Linux 可用保留目录与执行权限的复制工具；Windows 用本机目录复制工具并保留包内结构，若包有 Git symlink 则先确认客户端/文件系统支持，不能将链接文本误当资源。不能运行上游任意 setup/install 脚本来“验证”。完成后不把临时 checkout 当永久入口。

`license_files` 列出的文件在包根之外：从同一个提交复制到安装包的 `.ai-sma-source/<登记路径>`，保持其内容字节不变。登记的包内 LICENSE、版权、资源许可同样保留。上游已有 `SOURCE.md` 时保留原字节；本机安装时间等附加信息写入 `.ai-sma-source/` 的安装记录或项目回执。来源文字本身不能证明包正确；真正证据是固定提交的逐文件 blob 摘要。

注册表 `ready` 表示来源内容可核实，不代表全部服务和制作功能可用。`candidate`/`blocked` 项不可悄悄充当已安装必需技能。`license: unspecified` 明确表示上游未提供技能许可证，不能用框架商业条款或本模板 MIT 冒充；部署报告保留这一项限制。模型、音乐、字体和示范人物的许可独立记录。

## 已有版本与失败恢复

- 同来源、同精确提交、完整资源和权限核对通过：复用，不重复安装。
- 不同版本、同名不同来源或独立修改：保留原文件和入口，记录冲突；继续完成其余准备，列出具体冲突再决定处理。首版只接受注册表的精确提交，不自行推断兼容、不静默更新、不同时暴露第二个同名实体。
- 下载或复制失败：保留已核实包；重新执行部署时从实际状态继续。部分包不能被记作成功，也不能为了通过检查手填回执。
- 外部技能要求自动更新或改变制作框架时，以本项目选定路线和固定版本规则为准；需要更新时先更新来源清单并重验，不能在任务中悄悄升级。
- 完成后更新本机拥有索引、父级导航和 Claude 入口；项目索引只记录本项目选择，不复制本机全量目录。

## 检查与回执

```text
python agents/公共/工具/环境检查/检查环境.py --json
python agents/公共/工具/环境检查/检查环境.py --record
python agents/公共/工具/环境检查/检查环境.py --bind <skill-name>=<真实技能目录> --record
```

`python` 指实际检测可用的 Python 3：macOS/Linux 常为 `python3`，Windows 可为 `py -3`。`--bind` 只提供候选目录；仍完整校验，不能绕过摘要或共享目录检查。

默认检查全程只读，无网络下载、安装、登录或业务生成。`--record` 只把本次检查结果写到 `agents/项目/安装回执.json`。校验器用公开固定版本的全部包内文件摘要确认内容与来源、资源、入口身份和 Unix 执行权限，不把旧回执当成功证据。

客户端入口指向正确，只能报告 `entry_status: verified`；`discovery: not_verified` 需要部署智能体随后从当前客户端的实际技能清单或无副作用加载得到证据。不要执行一个会自动生成媒体或安装依赖的技能来测试发现。将客户端版本、技能名称与实际目录、观察时间及结果保存到 `agents/项目/客户端发现证据.md`，缺少实际会话时明确未验证。

部署交付分开列出：技能文件完整、客户端入口、客户端实际发现、工具可运行、登录/模型就绪、制作小样通过。检查器的 `ready` 只覆盖技能文件、入口路径与必要命令；不能据此宣布真实渲染或平台工作流已验证。任何必需技能仍缺失或冲突，都不能宣布技能安装完成。
