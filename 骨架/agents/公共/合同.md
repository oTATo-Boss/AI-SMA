# 交接合同

智能体之间只通过这些产物交接，不传聊天记录。产物都是 UTF-8 JSON，放在任务目录（`agents/工作/<任务>/`）里，`python3 agents/公共/工具/团队/校验产物.py <文件或任务目录>` 会检查字段。爆款库条目放 `agents/账号/爆款库/`。同类智能体同时做时各写各的文件（文件名带方向、方法或分组），由总负责人合并。

## 每个产物都有的字段

| 字段 | 内容 |
|---|---|
| `artifact` | 产物类型，见下表第一列 |
| `task` | 任务目录名；爆款库条目写采集它的任务 |
| `version` | 从 1 开始，返工一次加 1，旧版本另存为 `文件名.v<N>.json`（存档版本只留作历史，扫目录校验时跳过） |
| `owner` | 智能体编号，例如 `creative-director` |
| `created_at` | 北京时间，`YYYY-MM-DD HH:MM` |
| `evidence_refs` | 依据：爆款库条目 id、项目内文件路径或公开链接；没有依据写空列表并在内容里说明 |

## 产物

| artifact | 文件 | 谁写 | 必填字段 |
|---|---|---|---|
| `viral-reference` 爆款条目 | `agents/账号/爆款库/<id>.json` | 市场研究 | `id`、`platform`、`url`、`author`、`published_at`、`collected_at`、`metrics`、`baseline`、`outlier_ratio`、`media_reviewed`、`observed`、`inferred`、`transferable` |
| `opportunity-brief` 机会简报 | `调研/机会简报.json`（分路时 `调研/机会简报-<方向>.json`） | 市场研究，总负责人合并 | `opportunities`（每项：`topic`、`why_now`、`evidence_refs`、`audience_signal`、`mechanism_hints`）、`account_baseline`（分路简报写"待合并"，总负责人合并时从 `调研/账号表现.md` 填）、`gaps` |
| `idea-candidates` 创意候选 | `创意/候选-<方法>.json` | 创意总监 | `method`、`candidates`（每项：`id`、`one_liner`、`hook`、`beats`、`payoff`、`why`、`evidence_refs`、`borrowed_mechanism`、`difference_from_source`、`feasibility`）；`id` 用总负责人分的前缀，例如 `a1`、`b2` |
| `blind-candidates` 盲评候选 | `创意/盲评候选.json` | 总负责人合并 | `candidates`（每项字段同上，编号不变）；不写 `method`，也不透露是哪一路出的 |
| `idea-review` 创意评审 | `创意/创意评审.json` | 创意评审 | `blind`、`scores`（每项：`candidate`、`total`、`dimensions`、`risks`）、`pick`、`explore_pick`、`verdict`、`required_changes`、`similarity_flags` |
| `shot-list` 镜头表 | `方案/镜头表.json`（另附 `方案/制作方案.md`） | 导演 | `total_seconds`、`shots`（每项：`id`、`seconds`、`visual`、`action`、`camera`、`audio`、`text`、`assets`） |
| `asset-manifest` 素材清单 | `工程/素材清单.json`（分组时 `工程/素材清单-<分组>.json`） | 素材制作，总负责人合并 | `assets`（每项：`id`、`shot`、`type`、`path`、`source`、`tool`、`job_id`、`check`） |
| `review-report` 审片报告 | `检查/审片报告.json` | 审片 | `media`（`path` 从项目根目录写起、`sha256`）、`method`、`verdict`、`defects`（每项：`timecode`、`shot`、`severity`、`problem`、`cause`、`owner`、`fix`）、`strengths`、`publishable` |
| `experience-update` 经验更新 | `复盘/经验更新-<日期>.json` | 增长分析 | `mechanism`、`evidence`、`sample_size`、`window`、`confidence`、`status`、`recommendation` |

取值约定：

- `verdict`：创意评审为 `pass`、`revise`、`reject`；审片为 `pass`、`rework`、`reject`。
- `severity`：`blocker`（不能发）、`major`（明显影响观看）、`minor`（可以接受）。
- `fix`：`trim`（剪掉或调整）、`regenerate`（局部重生成）、`redo`（推翻重做）、`repackage`（只改封面文案）。
- `confidence`：`low`、`medium`、`high`；`status`：`hypothesis`（假设）、`verified`（有足够样本支持）。
- `media_reviewed`：真的看过视频画面、听过声音才写 `true`；只看了标题、封面、数据写 `false`。

## 三类信息分开写

爆款条目和机会简报里，`observed` 只写看到的事实和数据（含查看日期），`inferred` 写对成功原因的推测，`transferable` 写能迁移到新作品的方法。三者不能混写；推测不能当事实引用。

## 示例：机会简报

```json
{
  "artifact": "opportunity-brief",
  "task": "20261015_101500_今天的视频",
  "version": 1,
  "owner": "market-intel",
  "created_at": "2026-10-15 10:40",
  "evidence_refs": ["xhs-20261015-01", "xhs-20261015-02"],
  "opportunities": [
    {
      "topic": "日常物件的规则突然失效",
      "why_now": "近 7 天同类作品有 3 条互动达到作者常态的 5 倍以上",
      "evidence_refs": ["xhs-20261015-01"],
      "audience_signal": "评论里大量要求出续集",
      "mechanism_hints": ["预期建立 → 规则反转 → 荒诞结果"]
    }
  ],
  "account_baseline": "近 20 条中位互动 380（2026-10-15 查看）",
  "gaps": ["抖音数据未取得"]
}
```
