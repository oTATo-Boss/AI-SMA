# 项目执行细则

入口红线以项目根 `AGENTS.md` 为准；本文件补充执行方法，避免重复维护权限规则。

## 项目与角色

配置是项目目标、片型、形态、路线、平台和交付规格的唯一公共来源。每个任务只读与本次产物有关的上下文。导演负责呈现意图，编剧负责故事与文本，美术负责视觉规范，执行角色交付可验证素材；独立评审不代替执行角色修片。

## 技能使用

先查自己的 agent.yaml 和项目技能索引，再读取安装回执绑定的真实入口。skills 是已分配全集，preload_skills 是启动所需的少量核心入口；其余在匹配任务时完整读 SKILL.md，再按条件读取参考或子技能。

项目规格、派工范围和本人要求优先于技能的示例、平台默认和审批流程。小说技能仅借用适合的故事方法，不启动它自己的项目部署；网页动效要进入确定的媒体时间与导出流程；框架入口不改变已选择的制作路线。不得根据“有插件”推断模型、工具或账户已连接。

本机安装规则见 `技能安装.md`，公共来源由 `技能来源.json` 维护。技能问题记入任务并回报总负责人，制作中不修改共享源码。

## 交接与变更

按 `合同.md` 交接：输入版本、输出路径、责任、证据、已知限制和下一步均落盘。作品/集/场/镜头使用稳定 ID。上游改动后先定位影响范围，更新依赖状态，再安排必要返工；不重复生成无关镜头。

外部生成使用任务工具先登记请求意图，后登记服务任务 ID；不明结果先查原请求。凭据不进入请求记录或任何交付文件。

## 检查与交付

检查采用片型标准：事实与产品主张、故事与连续性、动画表达、音乐同步、技术规格各由相应角色执行。没有真实数据时不写已验证的增长结论，没有看/听时不写通过相应检查。

审片绑定精确文件版本与哈希；修改成片后原审片失效。单 agent 自检可以交付，但必须明确标注。最终包按当前项目交付规格组成；短片、长视频、系列和源工程不强行套用社媒三文件。

项目检查与环境检查分别运行。结构通过、安装完成、运行就绪和真实成片通过是不同证据。失败先定位原因；未验证事项写清范围和阻塞原因。
