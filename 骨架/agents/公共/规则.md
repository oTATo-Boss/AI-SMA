# 规则（细则）

红线和分工在项目根目录 `AGENTS.md`，所有智能体启动时自动加载。本文件只写细则，做项目维护或遇到相关问题时读。

## 1. 职责与协作

- 本项目负责内容策划、制作、交付和约定验收；按本人请求做账号研究和数据分析，维护必要的资产信息。内容范围见 `agents/账号/定位与策略.md`。
- 一个账号就是一个项目文件夹：本项目只服务这一个账号，不读取、不引用其他账号项目文件夹里的内容，也不和它们共用规范、资料或数据。客户端全局记忆不参考、不引用、不写入（入口红线 8）；浏览器里其他个人资料和标签页、其他项目留下的信息，都按其他账号的内容对待。项目检查会比对同级目录里其他账号项目的文件夹名，本项目文件里出现就报出来（只看文件夹名，不读里面的内容）；本人确认可以出现的名称写进 `agents/账号/账号配置.yaml` 的 isolation.allowed_terms。
- 本人负责最终决策、验收、发布和归档。发布不是制作任务的结束条件，项目不维护发布台账。
- 本人只和总负责人对话，总负责人派子智能体干活（`agents/README.md`）。已有明确授权持续有效，同一件事不重复问；开工阶段缺必要信息时问本人，做内容阶段只在总负责人说明书列的情况下问，同时继续不依赖它的工作。
- 检查按实际风险选择，不把 worktree、构建之类的习惯套到创作上。达到完成条件就停，不扩项。
- 同一时间一个文件只有一个写入者：同类子智能体同时做时各写各的文件，由总负责人合并；task.json 只通过任务管理工具写，任务总览由它自动生成，谁都不手改；日志只由总负责人写。改文件前重新读取，不覆盖别人刚写的内容。

## 2. 目录与权限

| 位置 | 用途 | 权限 |
|---|---|---|
| `AGENTS.md`、`CLAUDE.md` | 入口：红线、分工 | 改动按第 5 节 |
| `.claude/`、`.codex/` | 两个软件的设置、子智能体登记和写入保护 | `agents/` 和 `config.toml` 由生成脚本维护，不手改；其余改动先经本人同意 |
| `.ignore` | 搜索排除 | 可维护 |
| `agents/` | 智能体、账号档案、公共规则和工具、任务和日志 | 按任务读写 |
| `交付/` | 完整交付 | 只能新建全新目录；已有内容不改、不删、不改名、不移动、不追加 |
| `发布内容/` | 本人采用并归档的内容 | 只读 |
| `固定资产/` | 原始资产 | 只读，用时复制到任务目录 |

根目录不新增其他业务文件或目录。写入保护（Claude 的 `.claude/settings.json`、Codex 的 `.codex/hooks.json`）只是兜底，规则本身对所有客户端都有效。

**自动放行**：为了做内容时不中途找本人，项目预设了放行，本人第一次打开时在信任提示里确认。
- Claude：自动接受项目里的编辑和建目录、复制、移动；不用问就能运行 `python3`、`ffmpeg`、`ffprobe`、`npx remotion`、`npx hyperframes`、`npm install`、`npm run`、`node`、`heygen`、`codex exec`，以及网页搜索和抓取。
- Codex：信任项目后，项目里的命令本来就不用逐次批准；`agents/账号/账号配置.yaml` 的 autonomy.network_commands 为 true 时，命令还可以联网（调 RunningHub、HeyGen、装依赖）。
- 仍然要问或会被拦住的：删除文件（入口红线 1）、写项目以外的地方、上面没列的命令、写 `发布内容/`、`固定资产/` 和已有交付（写入保护拦截，放行规则绕不过它）。历史资料只用于追溯和查重，不当现行规则或模板；复用历史工程先复制到当前任务并核对旧路径。

```text
agents/
├── role/<名字>/   智能体：说明书、配置卡、记忆，有的带知识和工具
├── 账号/          账号档案：配置、事实、定位、规范、对标、爆款、数据、附录、历史资料
├── 公共/          本文件、交接合同、共用工具
└── 工作/          <任务>/（task.json、运行记录、产物）、任务总览、日志
```

任务子目录按需建立，用不到的不建：调研放机会简报和账号表现；创意放候选和评审；方案放制作方案、镜头表和提示词；工程放完整框架工程、素材和素材清单（连同依赖、媒体清单和许可）；产物放预览和成片；检查放审片报告和证据；交付暂存放待复制的完整包；复盘放经验更新；输入放参考、原片和来源；过程放旧快照和历史脚本。

## 3. 任务、授权与确认

- 做内容用 `content` 任务，按 `agents/role/总负责人/AGENT.md` 由总负责人派团队；"创意评审""成片审查"两项检查由任务工具卡住，本人只验收成品。
- 需要接续的执行任务以 `agents/工作/<任务>/task.json` 为唯一状态来源，用任务管理工具读写（`agents/role/总负责人/工具/任务管理/README.md`）。总览由工具生成，日志只记操作摘要。
- 授权与确认只登记本人真实原话或可定位的出处；确认绑定文件版本。核心方案改动后，受影响的确认重新取得，没变的部分不重复问。
- 当前制作任务所需的付费生成按入口红线 4 直接执行，无需本人另行确认，也不要求先填写工具授权；具体提交和恢复办法见对应工具说明（例如 `agents/role/素材制作/工具/runninghub-minimax-h3/README.md`）。技能默认的付费确认要求不另设关卡；工具和其他智能体不能扩大任务范围。
- 本项目不自动创建定时任务或后台服务；以后接入调度须本人授权，并读取同一任务记录，遵守确认、恢复和停止条件。

## 4. 账号、浏览器与凭据

- 浏览器只用本机 Chrome 里 `agents/账号/账号配置.yaml` 的 browser_profile 指定的个人资料，其他资料不用；工具列出的其他资料、标签页和账号信息不打开、不记录。Claude 的 Chrome 扩展装在多个资料里时，用前先 `list_connected_browsers`，有多个时让本人选，连上后打开平台创作者后台确认已登录。
- 发布平台的上传、上架、开通功能等操作由本人完成；制作任务所需的生成参考素材上传按入口红线 4 执行。
- 凭据按对应工具说明管理，不混入任务、提示词、日志、记忆或交付。

- 共享文件只写现在有效的内容，不写修改经过、作者或旧版本说明；过时内容在授权范围内直接改，经过由总负责人写进日志（子智能体写进自己的记录）。
- 一件事只写一处，其他文件引用。数据快照和外部知识保留日期和出处；附录顶部保留最后核对日期。推测标【待验证】，不编造。
- 发现新产品、账号、仓库、素材、路径或状态变化时当场更新附录；影响产品事实和方向时按授权同步账号信息和策略。
- 大改权限、授权、品牌等重要规则前先向本人说明；本人当次明确批准的方案可以直接实施。反复验证有效的经验写进对应智能体的经验或账号档案，一次失败只留任务证据和记录。
- 改完规则运行 `python3 agents/公共/工具/项目检查/检查.py`，失效链接和配置不一致要修完。

## 6. 技能使用

- 用技能前先查自己 `agent.yaml` 的 skills 和 `agents/SKILLS_INDEX.md`；没有合适的再从本机已装的技能里找。匹配就主动用，本人自建技能优先，不从零重写已有方法。
- 使用前完整读该技能的 SKILL.md，按它的方法做；参考和子技能只读当前需要的部分。
- 本人最新要求、项目权限、定位和内容规范优先于技能默认值，技能不扩大任务或授权。收集来的技能多以 YouTube、Instagram 为例，按小红书、抖音和定位调整。
- social-media 的六个技能进入对应阶段时必须实际使用，不只列名称。调用时把 `agents/账号/账号配置.yaml` 作为项目配置提供给技能。
- 共享技能源在项目外只读：发现问题记下来交总负责人，由本人决定是否修改。插件和系统技能的版本、连接以当前会话实际能力为准，缺能力如实说明。
- 新账号、换电脑或工具、技能报错时，先运行 `python3 agents/公共/工具/环境检查/检查环境.py`。它只检查并给出补法；安装软件或技能、登录账号要本人同意，登录和输入 Key 由本人操作。
- 技能索引只在用途、入口或分类变化时更新，只收本项目会用的技能。

## 7. 检查、交付与停止

- **终点。** 只做到本人要的成果：提示词、原片、预览、成片、完整内容包是不同终点；不顺手补封面文案、加场景或多做一轮。完成条件在任务开始时写明。
- **检查。** 每项写对象、方法、结果、证据和未验证范围；文件检查、抽帧、连续播放、试听分开报告。没做的写"未验证"，失败不写成通过，静帧不能证明运动和声音。
- **外部任务。** 任务 ID 和回包当场落盘，结果不明先查原任务，不盲目重提。当前任务的付费生成、参考素材上传和范围内返工按入口红线 4 执行；技能串联不扩大任务范围，登录仍由本人完成。
- **文件。** 工程、草稿、回包、素材副本、参考和检查留在当前任务目录；完整包在交付暂存整理检查后，由总负责人复制到 `交付/` 的全新目录，用任务工具登记，等本人验收。修订新增完整版本，旧交付不变，新版本重新等待验收。
- **结束。** 达到完成条件就更新任务、必要知识和记录（总负责人另写日志），简洁汇报后停止。缺证据或有实质缺项时，保存已有结果并如实说明，不为满足机器结束条件伪造交付。
- **反馈。** 报告里的建议不自动变成新的生产任务、持续监测或采集；方向结论经本人确认后才写回账号档案。

## 8. 日志和记录

- 日志只由总负责人写：`agents/工作/日志/YYYY-MM/YYYY-MM-DD.md`，新文件首行 `# YYYY-MM-DD`，北京时间。每次工作一行摘要 `- HH:MM · 事项 · 结果与验证 · 相关文件`，150 字以内，细节放任务目录。不建单文件 WORK_LOG。
- 子智能体收工在自己的 `记忆/记录/YYYY-MM.md` 记一行：`- YYYY-MM-DD · 任务目录 · 做了什么 · 结果 · 收到的意见 · 可能的经验`。上次提炼后满 10 条，总负责人派它提炼进 `经验.md`（不超过 3000 字），项目检查会提示。
