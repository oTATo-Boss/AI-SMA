# 项目检查

改规则、改工具、项目维护结束前，以及总负责人收工时运行。只读，标准库，几秒内完成。

```bash
python3 agents/公共/工具/项目检查/检查.py                                   # 在项目根目录运行
python3 agents/公共/工具/项目检查/检查.py --write-baseline <快照.json>        # 维护开始前记下受保护目录
python3 agents/公共/工具/项目检查/检查.py --baseline <快照.json> --json <报告.json>   # 维护结束后比较并留报告
```

| 检查 | 失败条件 |
|---|---|
| 规则文档链接 | 入口、团队说明、智能体说明书和知识、工具说明、账号档案等文档里的链接或路径指向不存在的文件（示例和占位路径跳过） |
| 任务记录 | 任何 task.json 校验出错 |
| 定位确认 | 定位状态写了"已确认"，但任务里没有本人通过的 positioning 确认，或确认的方案文件改过 |
| 团队 | 智能体包缺说明书、配置卡或经验；配置卡格式不对、编号重复；子智能体登记文件和 `.codex/config.toml` 不是最新；用到的技能没登记在技能目录；爆款库和任务目录里的交接产物不符合合同 |
| 隔离 | 本项目文件里出现同级其他账号项目的名称 |
| 受保护目录 | 与快照相比，交付/、发布内容/、固定资产/ 有新增、删除或改动（给了 --baseline 时） |
| 密钥 | `agents/.env` 里的密钥值或 Bearer 令牌出现在任何文本文件中（只报告位置，不输出内容） |
| 配置一致性 | `agents/项目/项目配置.yaml` 的交付文件名、时区与任务管理 `流程定义.json` 不一致；开工状态 stage 不是"开工中"或"已开工" |

另外报告几项提示（不判失败）：

- 阅读量：主对话开始时要读的字符数，以及每个子智能体动手前要读的字符数（入口、说明书、经验和"开工先读"里列的文件）。
- 记忆：哪个智能体的 `经验.md` 超过 3000 字，或者上次提炼以后的记录满 10 条，该提炼了。
- 规则重复：在 3 个以上文件里重复出现的关键规则。

快照和报告放当前维护任务的 检查/ 目录。
