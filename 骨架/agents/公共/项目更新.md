# 项目更新协议

更新属于项目维护，由总负责人协调；制作执行中不修改共享技能。使用部署时的实际 Python 解释器运行项目根目录的 `更新项目.py`。普通工作不需要常驻后台进程。

## 自动入口

进入项目工作先运行 `python 更新项目.py check --automatic --json`。自动检查最多每 24 小时一次，包括网络失败；`policy_skipped` 或没有新版本时继续原任务。`check_cached` 中仍有 `update_available` 时也要处理已有更新，不必再次联网。

- 策略 `auto`：对适用稳定版自主完成 plan、prepare、必要安装与 apply；存在活动执行或外部任务时先完成或保存安全检查点，再应用。常规更新不逐项询问。
- 策略 `notify`：仅报告新增的适用版本，等本人提出更新；`manual` 仅手动请求检查；`frozen` 固定当前版本。
- `check_unavailable`：继续完整可用的当前版本，不反复提醒同一失败。手动 `check --refresh` 可重新检查。
- `rate_limited` 或 `release_rejected`：保留当前版本，不采用有问题的发行。`check_stale` 表示检查期间配置或版本变化，沿用较新状态。只有 notify 为 true 时才重复告知检查结果变化。
- 兼容更新的范围不包括改项目方向、自动发布、修改模型选择或接管归属不明的共享技能。

## 接入及更新

已有 v2 项目从正式发行目录运行更新入口，指定 `--project` 和 `adopt`。接入保存原始基线、加入维护入口，并为旧任务工具增加带锁的适配层；旧工具保存在控制目录，既有任务不改写。v1 或缺失／损坏基线先报告，不能猜测归属。接入前结束其他旧客户端会话，防止仍在内存中的旧代码绕过新增协调。

1. `plan --to 版本`；也可指定由 check 返回的已验证缓存 `--source`。只使用正式发行；开发包仅限隔离测试。
2. `prepare --plan ID`。查看差异、冲突、目标暂存和实际环境检查。角色、路线和交付事实来自项目配置；用户直接修改造成冲突时保留文件，按差异协助合并后重新 plan。
3. 缺技能或工具时按暂存版本的技能来源和安装说明执行。完整包、共享资源、许可证及本机索引必须齐全，不用“已列入技能名”代替安装。
4. 再次 prepare、apply。任何必需项不满足时不启用部分新团队。检查后文件、配置或角色有变化时重新规划。
5. 文件更新与客户端发现分别验收。涉及客户端登记时，重载后保留实际发现输出，再执行 verify-client；不能用文件列表冒充实际发现。

## 执行检查点

开始主／子 agent 制作前登记 `begin --task 任务路径 --owner 唯一执行者标识`；每个执行者各自登记，结束后 `end`。总负责人确认执行者均结束且外部任务状态已核实后，使用 `checkpoint` 保存下一步、阶段和输入版本。执行命令也可由任务工具的对应入口调用。

异常退出的执行登记不因超时自行消失。先确认旧执行者已停止、检查任务和外部状态，再对原 owner 执行 checkpoint/end。外部提交结果不明时先恢复查询，不重复提交。新执行段绑定当前版本与合同，历史记录沿用对应合同快照。

## 共享技能维护

只在此计划确实需要替换共享包时执行 `dependency-begin --plan ID --source 来源ID --ref 固定提交 --path 完整包路径`。它只记录维护屏障，输出旧包备份位置，不安装软件。归属不明的现有共享包先保留；本人明确交由更新系统维护后才使用 `--adopt-existing`。

按回执先完整备份旧包，再由 Codex 按公开说明安装、同步分类索引和客户端入口，随后 `dependency-finish --source 来源ID` 验证。消费者未兼容或仍在执行时不替换。完整项目切换后才解除维护屏障。中断时使用 status 查看登记，不能另外提交重复维护。

如需恢复旧包，由 Codex 按登记的备份和来源执行恢复，再 `dependency-finish --source 来源ID --restore` 验证，最后 resume。新装而未启用的完整技能可以保留，不自动删除。

## 客户端证据

`verify-client --evidence 证据JSON路径` 接受项目内实际发现记录：`release_id` 必须等于 status 的当前发行标识；`clients` 按所选客户端包含 `method`（live-client 或 live-agent）、`transcript`（项目相对输出路径）、`sha256`、`roles`（全部启用角色ID，含主负责人）和 `skills`（本项目技能名）。记录须来自实际客户端输出并由操作者核对；本工具只校验记录完整性及摘要，不证明客户端输出内容真实，也不执行登录。技能加载变化同时在输出中核对当前绑定，不能沿用旧版本证据。

## 恢复与回退

中断后执行 resume，先恢复一致的旧状态，再重新规划。`rollback --transaction ID` 只回退最近一次受管变更；用户新增内容、历史任务与交付不回退。文件被再次修改或旧依赖不兼容时停止覆盖并列出具体阻塞。首次部署的 `--resume` 不用于项目升级。

更新状态分别说明文件、技能工具、客户端和制作实跑。登录、模型与样片未检查时仍为未验证。跨项目协调只覆盖已登记的 AI-SMA 使用者；项目级锁不约束任意外部程序。
