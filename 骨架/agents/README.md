# agents · 团队说明

本项目的智能体团队：本人只和**总负责人**对话，总负责人派 8 个子智能体干活，最后交付完整内容。每个智能体是 `role/` 下一个独立的文件夹，带自己的说明书、配置卡、知识、记忆和工具。

## 目录

| 位置 | 是什么 |
|---|---|
| `role/` | 9 个智能体，一个文件夹一个 |
| `账号/` | 账号档案：所有智能体共用的账号事实、定位、规范、对标、爆款和数据 |
| `公共/` | 共用的细则、交接格式和工具 |
| `工作/` | 每个任务一个目录，加任务总览和工作日志 |
| `SKILLS_INDEX.md` | 技能目录：作用、谁用、来源、许可 |

## 智能体

| 智能体 | 编号 | 负责 |
|---|---|---|
| [总负责人](role/总负责人/AGENT.md) | account-lead | 主对话：和本人对话，拆任务、派子智能体、合并、裁决、交付、记录 |
| [市场研究](role/市场研究/AGENT.md) | market-intel | 看别人的作品：爆款、对标、热点、评论，写爆款库和机会简报 |
| [创意总监](role/创意总监/AGENT.md) | creative-director | 按指定方法出创意候选 |
| [创意评审](role/创意评审/AGENT.md) | creative-critic | 盲评创意、查证据和相似度，选方案 |
| [导演](role/导演/AGENT.md) | film-director | 制作方案、镜头表、提示词和声音设计 |
| [素材制作](role/素材制作/AGENT.md) | media-producer | 图片、视频片段、配音和音效 |
| [后期](role/后期/AGENT.md) | post-producer | 剪辑、声音、字幕、封面、文案和打包 |
| [审片](role/审片/AGENT.md) | quality-reviewer | 真看真听成片，判断能不能发，指派返工 |
| [增长分析](role/增长分析/AGENT.md) | growth-analyst | 看本账号自己的数据，按创意机制归因，更新经验 |

出创意和评创意、做成片和审成片由不同的智能体负责，没有人给自己打分。

## 怎么协作

- **开工阶段**（`账号/账号配置.yaml` 的 stage 是"开工中"）：总负责人带本人回答开工问题、做定位，方向由本人确认。
- **做内容阶段**：本人说一句"做一条视频"，总负责人按自己的说明书派活：调研 → 创意 → 评审 → 方案 → 制作 → 合成 → 审片 → 交付，中途不问本人；评审和审片不过就返工，轮数有上限。
- 智能体之间只传文件（格式见 `公共/合同.md`），不传聊天记录。同一时间一个文件只有一个写入者：同类智能体并行时各写各的文件，由总负责人合并。子智能体交回产物后就关掉，有的软件把没关的也算在同时干活的上限里。

## 每个智能体的结构

```text
role/<名字>/
├── AGENT.md      说明书：你是谁、你交什么、开工先读、怎么做、质量标准、不做什么、收工
├── agent.yaml    配置卡：编号、名字、派工说明、技能、工具、思考深度
├── 记忆/
│   ├── 经验.md   提炼过的经验，开工必读，不超过 3000 字
│   └── 记录/     每次任务一行，按月一个文件
├── 知识/         （有才建）入职带的方法和标准
└── 工具/         （有才建）自带脚本和用法
```

- **知识**是模板带来的方法；**记忆**是在这个账号干出来的经验，只属于这个账号；**账号档案**（`账号/`）是所有智能体共用的事实。
- 说明书只写通用说法（"读文件""运行命令"），不写哪个软件专用的工具名；路径从项目根目录写起。

## 记忆怎么长

| 谁 | 写到哪 | 什么时候 |
|---|---|---|
| 智能体自己 | 自己的 `记忆/记录/`；提炼时重写自己的 `经验.md` | 每次收工；被派去提炼时 |
| 总负责人 | 各智能体 `经验.md` 的"本人要求"一节，记本人原话 | 本人对某个角色提要求时 |
| 增长分析 | 相关智能体 `经验.md` 的"已验证""待验证"，只追加 | 复盘时 |

评审、审片的意见和本人的验收意见，由总负责人派回负责的智能体时带上，由它自己记进记录。上次提炼后记录满 10 条就提炼一次，项目检查会提示哪些该提炼了。关于整个账号的偏好只写 `账号/偏好.md`。

## Codex 和 Claude

- `公共/工具/团队/生成角色.py` 读每个子智能体的 `agent.yaml`，生成 `.codex/agents/<编号>.toml` 和 `.claude/agents/<编号>.md`。这两份只有名字、派工说明、思考深度、工具限制、预加载的技能和一句"先读你的说明书和经验"，所以改说明书马上生效；改了配置卡要重新运行脚本。它还生成 `.codex/config.toml`，写同时干活的子智能体上限。
- Codex 只在本人信任这个文件夹后才读 `.codex/` 里的设置；项目自带的写入保护还要本人在 Codex 里批准一次。部署后新开一个对话，子智能体才会被认出来。
- 写入保护两个软件都接：Claude 用 `.claude/settings.json`，Codex 用 `.codex/hooks.json`，调用同一个脚本。

## 加一个智能体

1. 在 `role/` 下新建文件夹，写 `AGENT.md`（按上面七节）、`agent.yaml`（编号不能和别人重复）、`记忆/经验.md`（照抄已有的模板）。
2. 在本文件和总负责人说明书的团队表里各加一行，写清什么时候派它。
3. 运行 `python3 agents/公共/工具/团队/生成角色.py`，再运行项目检查。
