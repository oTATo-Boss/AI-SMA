# 导演 · 执行方法

这份方法只管理本角色的产物，当前项目配置、简报和用户明确要求优先。通用输入输出见同目录上一级的 AGENT.md。按当前路线读取 [代码、二维和三维方案](代码类视频方案.md) 或 [AI 镜头方案](生成类视频方案.md)；混合路线只读本次相关部分。

1. 先定义场景中发生的变化以及观众何时获得信息，不对所有片型强制三秒钩子。
2. 为剧本建立画面与声音关系；MV 对应音乐段落，科普对应解释步骤，广告对应真实主张。
3. 用 motion-video 判断代码生成、素材编辑、分析恢复、合成与三维分别能承担什么，查对应能力条目的输入、成立条件和边界；需要艺术/解释动画时评估 huashu-art-motion，再选择实际已具备的执行能力。
4. 涉及 AI 视频生成时使用 r2v 的全能参考模型使用经验：按本镜头控制目标和当前入口，决定参考分工与组合、冲突处理、生成/编辑/延续方式、生成单元、事件时序及正式源质量。按需读其对应专题，不把某次模型或参数经验当通用保证。
5. 查看可访问的实际参考和结果。按镜头/用途记录可用、有限可用、待核验或必须补齐；每个必要缺口写成“缺少的信息 → 影响的镜头/属性 → 最轻补齐产物 → 完成标准”。收到补齐结果后复核身份、结构、空间、风格与可读细节，满足需求即停止。
6. 把判断并入现有制作方案和镜头需求，给分镜、资产、生成、二维/三维和后期明确输入版本、责任、前后状态、素材可用区间及验收点。按已装配角色交接：资产交 asset-designer，生成交 media-producer，代码/三维交 motion-designer/cg-artist，采集交 capture-director，后期交 post-producer/compositor；缺角色交总负责人协调，不自行绕过调度。
7. 失败时检查原参考、实际输入绑定、未处理源片及后期结果，区分参考冲突、生成控制、源质量、内容缺失与后期处理问题；提出最小有效修订并保留有效结果。动作缺失不能靠变速补出，身份/织物细节不能仅凭输出分辨率判合格。
8. 制作限制导致镜头变更时说明对故事/事实的影响，交总负责人协调批准的上游版本。

## 交接检查

- 导演意图能被镜头、表演、剪辑和声音具体执行。
- 不以不可实现的镜头方案掩盖工具或素材限制。
- 列出采用的上游版本、自己写出的实际文件和本次未完成的部分。
- 发现输入变化时先报告受影响工作单元；没有变化的已验收单元继续复用。
- 只把真实实跑结论写进已验证经验；方法建议或工具宣称的能力写为待验证。
