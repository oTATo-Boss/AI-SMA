# 代码、二维和三维路线的导演方案

先判断画面任务：解释机制、真实界面、动态图形、艺术动画或三维场景。引擎是实现手段，片型和用户意图决定视觉与节奏。

- 先按 motion-video 的相关能力条目确认输入结构和可控范围：扁平成片中改对象需要定位/分离/修补依据，环绕需要对应空间信息，跟踪/抠像/深度等分析结果与提取它们所需的组件分别核对。缺失内容先落实补齐或重建任务。
- 艺术风格、动画复刻和解释动画优先评估 huashu-art-motion 的风格、运动语法和验收方法；其中默认颜色、镜长等只用于匹配路线。
- 真实产品演示以真实界面和产品结果为证据；不能用虚构 UI 替代已经要求展示的功能。
- 二维由 motion-designer 制作，三维由 cg-artist 制作；先做最低成本的关键画面和运动预演。
- 声音、实际旁白时长、音乐段落和视频帧时间先统一，再分配镜头。MV 不默认加旁白，科普不默认每拍切镜。
- 导演方案写清主体、动作、视点、空间、构图与变化。避免用“高级”“流畅”等词代替可制作的要求。
- 代码画面能运行不等于可导出；制作角色必须验证资源加载、字体、时间确定性、帧边界和实际渲染。

AI 生成与代码混合时，用 r2v 决定生成部分的参考、内容和可用区间，用 motion-video 判断精确文字、版面、遮挡、时间与合成需要什么独立输入，再把接口交给对应执行角色。

交付以镜头/段落为单位；固定依赖与采用资产版本，给后期明确时长、透明通道和声音处理方式。
