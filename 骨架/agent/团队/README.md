# 团队 · 总控协议

本人一句话下达创作任务（例如"今天做一条视频"），由当前会话的 agent 担任**总控**，按本协议调度 8 个专业角色完成，中途不找本人确认，最后交付完整成品。角色定义在本目录各子目录的 `角色.md`，交接格式见 [合同](合同.md)。

## 角色

| 角色 | 负责 | 产出 |
|---|---|---|
| [市场研究](市场研究/角色.md) | 爆款、对标、热点、评论；找出高于作者常态的作品并拆解 | 机会简报、爆款库条目 |
| [创意总监](创意总监/角色.md) | 用不同方法产出多个创意候选 | 创意候选 |
| [创意评审](创意评审/角色.md) | 盲评候选、对照证据、查和原作的相似度，选定方案 | 创意评审 |
| [导演](导演/角色.md) | 把选定创意变成脚本、分镜、镜头表和声音设计 | 制作方案 |
| [素材制作](素材制作/角色.md) | 按方案生成图片、视频和音频 | 素材清单 |
| [后期](后期/角色.md) | 剪辑、声音、字幕、封面、标题正文标签、打包 | 成片和内容包 |
| [审片](审片/角色.md) | 实际看成片和听声音，定位问题并指派返工 | 审片报告 |
| [增长分析](增长分析/角色.md) | 发布后的数据、和账号常态比较、更新经验 | 经验更新 |

创意评审和审片必须由独立的角色完成，不能由出方案或做成片的角色给自己打分。

## 什么时候启用

- 一句话创作任务、完整内容包：按下面的标准流程。
- 只要调研、只要创意或只做某一步：只派对应角色，不走全流程。
- 问答、改规则、单个小修改：不启用团队。

## 开工前提

1. **定位已确认。** `../规范/定位与策略.md` 的定位状态是"已确认"。不是的话，先按定位 SOP 做研究，把方向方案作为**唯一一次阻塞**交本人确认（入口红线第 7 条），确认后再开工。
2. **自主设置。** 读 `../规范/账号配置.yaml` 的 autonomy：模式、并行上限、轮数上限。full 模式中途不找本人确认；checkpoints 模式在选题和制作方案处等本人确认。
3. **登记任务。** 用任务工具新建 `auto-video` 任务，选定创意、成片审查两项检查由工具卡住：没通过就进不了"制作""交付"。

## 标准流程（自主视频）

| 阶段 | 派谁 | 并行方式 | 进入下一步的条件 |
|---|---|---|---|
| 1 调研 | 市场研究（爆款与对标、热点与评论两路并行）；增长分析读本账号近期表现 | 并行 | 总控合并成一份机会简报 |
| 2 创意 | 创意总监 3 路：同赛道机制借鉴、跨赛道迁移或热点重组、原创发散 | 并行，各自独立 | 候选总数不少于 autonomy.idea_candidates_min |
| 3 评审 | 创意评审盲评（去掉方法标签） | 单独 | 有方案过线；都不过就回到 2，最多 autonomy.idea_rounds_max 轮 |
| 4 方案 | 导演 | 单独 | 制作方案写完 |
| 5 制作 | 素材制作（多路并发，不超过工具允许的并发数）；后期同时准备封面和文案方案 | 混合 | 素材齐全并通过素材自检 |
| 6 合成 | 后期 | 单独 | 成片、封面、文案齐全 |
| 7 审片 | 审片 | 单独 | 通过；不通过就按报告把问题派回负责角色返工，每处最多 autonomy.rework_rounds_max 轮 |
| 8 交付 | 后期打包，总控写依据卡 | 单独 | 内容包复制到 `交付/` 新目录，任务等本人验收 |

制作细节沿用 `../sop/生成类视频.md`、`../sop/代码类视频.md` 和 `../sop/发布材料交付.md` 的步骤和检查；其中要本人确认的步骤，在 full 模式下由创意评审和审片代替。

发布后数据到了（本人提供或授权读取），由增长分析更新经验，影响下一次的选题和创意取舍。

## 总控怎么做

- **只编排，不代工。** 总控负责拆任务、派角色、合并产物、裁决分歧、控制上限和记录；专业工作交给对应角色。
- **派工要具体。** 每次派工写清：任务目录、要读的产物、要交的产物和位置、本次的限制（时长、平台）。角色之间不直接传聊天记录，只传合同里的产物。
- **并行有上限。** 同时工作的角色不超过 autonomy.max_parallel_agents；同一阶段的独立工作才并行，有依赖的按顺序。
- **裁决留痕。** 评审和导演、审片和后期意见不一致时，总控按证据裁决，把理由写进任务记录。
- **留探索名额。** 选创意时按 autonomy.explore_ratio 给探索性方案留比例，不能永远只选最保守的高分方案。
- **上限不能放宽。** 并行数和返工轮数是本人定的上限，任何角色都不能为了"再试一次"突破；到上限就停。

## 什么时候停下来找本人

只在这些情况发阻塞报告，写清已完成什么、卡在哪、需要本人做什么：

- 定位没确认（开工前提 1）；
- 需要登录、扫码、授权或付费服务的 Key；
- 返工轮数用完仍没达标；
- 素材版权、平台规则或法律风险拿不准。

其他问题由团队自己解决，不中途征求意见。

## 记录

- 任务状态写 `task.json`：每个阶段更新 phase 和 next_action；创意评审、成片审查用 `check` 登记并附产物文件作证据。
- 所有产物放在任务目录，按 [合同](合同.md) 命名；付费生成的任务 ID 当场写进 external_jobs。
- 交付时附 `依据卡.md`：选了哪个创意、依据哪些爆款和数据、审片结论、还有什么风险。
