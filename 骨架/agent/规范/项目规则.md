# 项目规则（细则）

红线、启动和任务路由在项目根目录 `AGENTS.md`，所有 agent 启动时自动加载。本文件只写细则，做项目维护或遇到相关问题时读。

## 1. 职责与协作

- 本项目负责内容策划、制作、交付和约定验收；按本人请求做账号研究和数据分析，维护必要的资产信息。内容范围见 `定位与策略.md`。
- 一个账号就是一个项目文件夹：本项目只服务这一个账号，不读取、不引用其他账号项目文件夹里的内容，也不和它们共用规范、资料或数据。客户端全局记忆不参考、不引用、不写入（入口红线第 8 条）；浏览器里其他个人资料和标签页、其他项目留下的信息，都按其他账号的内容对待。项目检查会比对同级目录里其他账号项目的文件夹名，本项目文件里出现就报出来（只看文件夹名，不读里面的内容）；本人确认可以出现的名称写进 `账号配置.yaml` 的 isolation.allowed_terms。
- 本人负责最终决策、验收、发布和归档。发布不是制作任务的结束条件，项目不维护发布台账。
- agent 按目标组织工作、选工具、做必要检查、整理交付，不要求本人传递内部命令。已有明确授权持续有效，同一件事不重复问；缺必要信息、授权或关键判断时及时问，同时继续不依赖它的工作。
- 检查按实际风险选择，不把 worktree、构建之类的习惯套到创作上。达到完成条件就停，不扩项。
- 多个 agent 同时工作：先看任务总览和相关 task.json，登记处理者；接手前确认原处理者已停止或完成交接；改文件前重新读取，不覆盖别人刚写的内容。采用什么协作方式按本人当次安排。

## 2. 目录与权限

| 位置 | 用途 | 权限 |
|---|---|---|
| `AGENTS.md`、`CLAUDE.md` | 入口：红线、启动、路由 | 改动按第 5 节 |
| `.claude/` | Claude Code 配置和写入拦截 | 改动先经本人同意；`agents/` 由生成脚本维护 |
| `.codex/agents/` | Codex 的角色配置 | 由 `agent/tools/团队/生成角色.py` 生成，不手改 |
| `.ignore` | 搜索排除 | 可维护 |
| `agent/` | 规则、记录、工程、素材副本、中间产物、检查 | 按任务读写 |
| `交付/` | 完整交付 | 只能新建全新目录；已有内容不改、不删、不改名、不移动、不追加 |
| `发布内容/` | 本人采用并归档的内容 | 只读 |
| `固定资产/` | 原始资产 | 只读，用时复制到任务目录 |

根目录不新增其他业务文件或目录。写入拦截（`.claude/settings.json`）只对 Claude Code 生效，其他客户端同样遵守本表。历史资料只用于追溯和查重，不当现行规则或模板；复用历史工程先复制到当前任务并核对旧路径。

```text
agent/
├── 规范/          长期依据（分工见第 5 节）
├── 账号数据/      原始资料与正式分析报告
├── 工作/<任务>/   task.json、运行记录.jsonl，按需建子目录
├── log/           日志和自动生成的任务总览
├── sop/           任务执行方法
├── tools/         项目工具
├── 附录/          产品、仓库、账号、素材位置
└── 历史资料/      停用资料
```

任务子目录按需建立，用不到的不建：输入放参考、原片、素材和来源；方案放脚本分镜、设计和提示词；工程放完整框架工程（连同依赖、媒体清单和许可）；产物放预览和成片；检查放报告和证据；交付暂存放待复制的完整包；过程放旧快照和历史脚本。

## 3. 任务、授权与确认

- 一句话创作任务用 `auto-video` 流程，按 `agent/团队/README.md` 由总控调度角色。autonomy.mode 为 full 时没有本人的中途确认，创意评审和成片审查两项检查由任务工具卡住，本人只验收成品；角色只改 `agent/团队/*/角色.md`，改完运行生成脚本。
- 需要接续的执行任务以 `agent/工作/<任务>/task.json` 为唯一状态来源，用任务管理工具读写（`agent/tools/任务管理/README.md`）。总览由工具生成，日志只记操作摘要。
- 选定的 SOP 路径登记到 inputs；当前步骤编号、文件和恢复条件写 next_action。步骤编号不替代机器阶段。
- 授权与确认只登记本人真实原话或可定位的出处；确认绑定文件版本。核心方案改动后，受影响的确认重新取得，没变的部分不重复问。
- 付费服务的授权范围和恢复办法写在对应工具目录（例如 `agent/tools/runninghub-minimax-h3/AGENTS.md`）；没写明持续授权的，每次提交前先问本人。工具和其他 agent 都不能扩大授权。
- 本项目不自动创建定时任务或后台服务；以后接入调度须本人授权，并读取同一任务记录，遵守确认、恢复和停止条件。

## 4. 账号、浏览器与凭据

- 浏览器用本机 Chrome 的「{{浏览器资料}}」资料，其他资料不用；工具列出的其他资料、标签页和账号信息不打开、不记录。Claude 的 Chrome 扩展装在多个资料里时，用前先 `list_connected_browsers`，有多个时让本人选，连上后打开平台创作者后台确认已登录。
- 上传、上架、开通功能等平台操作由本人完成。
- 凭据按对应工具说明管理，不混入任务、提示词、日志、记忆或交付。

## 5. 信息归属与维护

| 内容 | 唯一位置 |
|---|---|
| 红线、启动、任务路由 | 根目录 `AGENTS.md` |
| 细则：职责、目录、授权、技能、记录 | 本文件 |
| 本人、产品、账号事实 | `账号信息.md`（本人维护，经同意 agent 可更新） |
| 目标、受众、内容体系、变现、测试 | `定位与策略.md` |
| 品牌、声音、制作、包装、分发检查、验收 | `内容与交付.md` |
| 规格参数：画幅、封面、声音、生成默认值、交付命名、时区 | `账号配置.yaml` |
| 偏好、反馈、教训 | `偏好与经验.md` |
| 有来源的外部知识 | `外部知识.md` |
| 候选想法与立项链接 | `选题池.md` |
| 执行步骤 | `agent/sop/` |
| 技能选型与入口 | `agent/SKILLS_INDEX.md` |
| 工具用法 | `agent/tools/README.md` 和各工具 AGENTS.md |
| 产品、仓库、账号、素材位置 | `agent/附录/` |
| 原始数据与正式报告 | `agent/账号数据/` |
| 任务状态 / 操作经过 | 各 `task.json` / `agent/log/` |

- 共享文件只写现在有效的内容，不写修改经过、作者或旧版本说明；过时内容在授权范围内直接改，经过写日志。
- 一件事只写一处，其他文件引用。数据快照和外部知识保留日期和出处；附录顶部保留最后核对日期。推测标【待验证】，不编造。
- 发现新产品、账号、仓库、素材、路径或状态变化时当场更新附录；影响产品事实和方向时按授权同步账号信息和策略。
- 大改权限、授权、品牌等重要规则前先向本人说明；本人当次明确批准的方案可以直接实施。反复验证有效的经验写进对应规范，一次失败只留任务证据。
- 改完规则运行 `python3 agent/tools/项目检查/检查.py`，失效链接和配置不一致要修完。

## 6. 技能使用

- 用技能前先查 `agent/SKILLS_INDEX.md`；没有合适的再从本机已装的技能里找。匹配就主动用，本人自建技能优先，不从零重写已有方法。
- 使用前完整读该技能的 SKILL.md，按它的方法做；参考和子技能只读当前需要的部分。
- 本人最新要求、项目权限、定位和内容规范优先于技能默认值，技能不扩大任务或授权。收集来的技能多以 YouTube、Instagram 为例，按小红书、抖音和定位调整。
- 社交内容任务启动、接续或跨阶段先用 social-media-router；social-media 的六个技能进入对应阶段时必须实际使用，不只列名称。调用时把 `agent/规范/账号配置.yaml` 作为项目配置提供给技能。
- 共享技能源在项目外只读：发现问题写日志，由本人决定是否修改。插件和系统技能的版本、连接以当前会话实际能力为准，缺能力如实说明。
- 新账号、换电脑或工具、技能报错时，先运行 `python3 agent/tools/环境检查/检查环境.py`。它只检查并给出补法；安装软件或技能、登录账号要本人同意，登录和输入 Key 由本人操作。
- 技能使用效果和验证结果写日志；技能索引只在用途、入口或分类变化时更新，只收本项目会用的技能。

## 7. 检查、交付与停止

- 完成条件在任务开始时写明。检查记录对象、方法、证据和未验证范围；文件检查、抽帧、连续播放、试听分开报告。
- 交付顺序：任务目录内制作、检查、整理成完整包 → 复制到 `交付/` 的全新目录 → 用任务工具登记 → 等本人验收。修订新增完整版本，旧交付不变，新版本重新等待验收。
- 达到完成条件后更新任务、必要知识和日志，简洁汇报。

## 8. 日志

- 路径 `agent/log/YYYY-MM/YYYY-MM-DD.md`，新文件首行 `# YYYY-MM-DD`，北京时间。
- 每次工作一行摘要 `- HH:MM · agent · 事项 · 结果与验证 · 相关文件`，150 字以内，细节放任务目录。不建单文件 WORK_LOG。
