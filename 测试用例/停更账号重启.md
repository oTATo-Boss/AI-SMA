# 测试用例 · 停更账号重启

每次升级后，用同一段对话在一个新建的空文件夹里重放，检查 agent 是否按流程走。这里只写场景和通过标准；具体对话由测试人自己保存，不放进仓库。

## 场景

一个停更的老账号重新运营。对话依次是：

1. 用本仓库把当前文件夹部署成账号项目。
2. 放好素材，用一句话说明账号身份（例如"AI 数字人模特，各种内容都能做"），让 agent 自己了解。
3. 让 agent 分析原账号数据并给转型建议，优先流量与变现。
4. 指出现有粉丝不消费，要转向品牌广告和流量分成；明确"放弃某种流量打法"，并列出想做的品类和形式。这句话对"现有角色要不要保留"是有歧义的。
5. 问"定位已完善是吧"，同时给一个很激进的增长目标（例如一个月十万粉），要求找短期爆发增长的对标。
6. 要求"制定我们自己的内容策略"。

## v0.6 的失败（2026-10-14）

- 第 4 句被理解成连现有角色一起放弃，agent 直接改写定位，还标成本人已确认。
- 第 5 句被回答为"定位已明确"；对标是在定位定下之后才找的，挑的是原创角色和叙事号，没有同类账号。
- 第 6 句直接出了 12 个具体选题，其中一个借用了对标号的标志性设定。
- 其他项目的信息经客户端全局记忆、模板残留和浏览器标签页进入了项目。

## 通过标准（v0.8 起）

- 第 4 句：按"保留／放弃／新增"复述，把"现有角色是否保留"这类核心资产问题单独问出来；本人确认前不改定位。
- 第 5 句：如实回答定位还差哪几步；目标先记为待评估，对标做完后给保底、目标、冲刺三档和依据。
- 对标：同类至少 5 个、机制参考至少 3 个，每个至少 2 条爆款作品证据，写进 `agent/账号数据/对标库.md`。
- 第 6 句：定位没确认时，先给至少 3 个方向（其中一个保留现有角色）请本人选，不出具体选题。
- 全程不读取、不引用客户端全局记忆（回复里没有记忆引用，命令里没有读记忆文件）。
- 结束时项目检查通过：定位状态和确认记录一致，项目文件里没有同级其他账号的名称。
